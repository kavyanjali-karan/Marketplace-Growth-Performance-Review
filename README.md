# Marketplace Revenue Analytics

[![CI](https://github.com/kavyanjali-karan/marketplace-growth-performance-review/actions/workflows/ci.yml/badge.svg)](https://github.com/kavyanjali-karan/marketplace-growth-performance-review/actions/workflows/ci.yml) [![tests: 20 passed](https://img.shields.io/badge/tests-20%20passed-2ea44f)](tests/) [![license: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

Everyone in the business "knew" Electronics was the big category. Nobody
could say how big. This project joined up 75,000 **simulated** orders
from 10,000 buyers and put a number on it: Electronics drives 44.8% of
all income (₹3.4B of ₹7.6B), while returns and cancellations quietly eat
8.0% of orders. On top of the analysis sits a Power BI reporting layer
with DAX measures covering 7 performance areas: earnings, buyers,
sellers, and the rest.

It's an **Indian** marketplace by design (Faker's `en_IN` locale: UPI and
Net Banking payments, a Diwali and Independence Day sale calendar), so
amounts are in rupees throughout. ₹7.6B works out to roughly $91M at
~₹83/$; shares and rates don't care about the currency.

**Try the [live dashboard](https://kavyanjali-karan.github.io/Marketplace-Growth-Performance-Review/dashboard.html)**,
regenerated by CI on every push.

## The reporting problem

Growth had outrun the spreadsheets. Category profitability lived in one
file, per-order return flags in another, seller ratings in a third. The
44.8% Electronics share, the 5.0% return rate and the 3.0% cancellation
rate were all sitting in the raw orders, unaggregated. Festive-season
pricing and seller decisions were being made on instinct because the
unified view simply didn't exist.

## What this repo does

1. **Star-Schema Dimensional Model** — Customer, product, seller, and date dimensions feeding a central `fact_orders` table with 75,000 transaction records
2. **7 Power BI Dashboards** — Marketplace overview, revenue trends, order analysis, seller performance, product analysis, customer segmentation, and category deep-dives
3. **DAX Measure Library** — Reusable measures for revenue, order counts, average order value, seller ratings, and customer lifetime metrics
4. **Metric Governance** — Standardized indicator definitions to align calculations across all 7 reporting areas

## Data

Simulated Indian marketplace (similar in shape to Olist, localized to India):

| Dataset | Records | Description |
|---------|---------|-------------|
| `orders.csv` | 75,000 | Orders with customer, seller, product, status, dates, amounts |
| `customers.csv` | 10,000 | Buyer profiles with segment, location, signup date |
| `products.csv` | Product catalog | Category, subcategory, brand, pricing |
| `sellers.csv` | Seller profiles | Tier, region, rating, join date |
| `payments.csv` | Payment records | Method, installments, status |


Pages only publishes after Actions rebuilds both dashboards from the
committed data, so the live site and this README are always telling the
same story.
